# 站内文档编写与样式约定

适用于本 feature 的正文、导航、搜索、渲染和布局。修改前先读取仓库根目录 `AGENTS.md`、`web/AGENTS.md`；本文件补充文档领域约定，不替代上级规则。涉及首页或分组状态板时也按这里的视觉约定保持一致。

## 内容与入口

| 路径 | 职责 |
| --- | --- |
| `content/*.md` | 站内文档正文，已有页面的日常更新入口 |
| `pages.ts` | 分类、标题、描述、slug 和阅读顺序 |
| `lib/content.ts` | 通过 `?raw` 导入正文并注册到 `DOC_CONTENT` |
| `lib/markdown.ts` | 模板替换、标题锚点和特殊标记解析 |
| `components/doc-article.tsx` | 正文渲染，复用共享 Markdown 与代码块组件 |
| `components/doc-search.tsx` | 按页面和二、三级标题搜索 |
| `components/doc-navigation.tsx`、`doc-toc.tsx` | 左侧导航、当前页目录 |
| `components/doc-widgets.tsx` | 可复制接口地址和实时分组状态 |
| `index.tsx` | 公共布局、移动导航和上一篇/下一篇 |
| `../../routes/docs/` | `/docs` 与 `/docs/$slug` 路由 |

根目录 `视频统一接口.md` 是独立的对外接口说明，站内正文是 `content/videos.md`，两者没有自动同步。修改视频契约时先核对实现和根目录说明，再同步站内内容；纯排版调整无需机械改动两份文件。OnlyArt 是独立项目，其实现从用户指定的工作区读取，不能把某台机器的绝对路径当作项目依赖。

## 写作风格与事实依据

- 面向实际使用者，直接说明操作、请求与结果。中文正文、英文技术标识；不写营销口号或描述网页的视觉设计。
- 延续相邻文章的顺序：简短介绍、准备条件、配置或接口、可运行示例、验证方式、常见错误。按内容取舍，不强制每篇套满所有章节。
- 页面标题由 `pages.ts` 和布局生成，正文从段落或 `##` 开始，不重复写 `#` 标题。`##` 分区、`###` 子步骤，不依赖四级标题进入目录。
- 步骤用有序列表；字段、模型能力和协议差异用表格。错误处理写具体提示、原因与下一步，不凭空归因上游故障。
- 以当前代码、实际配置、用户提供的接口说明和提供商官方资料为依据。外部客户端的安装命令、配置字段与协议需核对当前官方文档；涉及 Codex/OpenAI 时使用 `openai-docs` 技能。
- 区分本站公开协议与提供商原生能力，不把未开放的接口、模型或参数写成可用。日期仅用于有依据的能力核对，不在纯文字更新时刷新日期。
- 接口与模型价格优先链接 `/pricing`，分组信息优先使用实时组件。确需静态列出当前价格或倍率时说明时效和来源，避免把示例数字写成保证。
- 触及计费规则时按根目录规定完整读取 `.agents/rules/billing.md`；涉及认证说明时核对实际流程和适用的安全规则。不得通过文档暗示客户端检查能代替服务端约束。
- 示例只能使用占位密钥、公开任务 ID 和示例素材，禁止包含真实凭据、个人信息或生产内部地址。说明哪些输入必须替换；Shell 与 PowerShell 示例分别保证语法正确。
- 保留 new-api、QuantumNous 的署名、版权和官方资料入口。

## Markdown 格式

动态内容使用这三个变量，避免在通用示例中写死部署名称或网关地址：

| 变量 | 含义 |
| --- | --- |
| `{{SITE_NAME}}` | 当前站点名称 |
| `{{BASE_URL}}` | 当前网关地址，不含协议端点路径 |
| `{{WORKBENCH_URL}}` | 工作台地址，由 `pages.ts` 配置 |

- OpenAI 兼容请求通常在 `{{BASE_URL}}` 后追加 `/v1`；其他协议按实际路径填写，不能给所有 SDK 强制套同一地址格式。
- 站内文章链接写 `[视频生成](/docs/videos)`。控制台链接使用真实路由；新增链接时检索 `web/src/routes/`，不要凭旧文档猜路径。
- 锚点由 `slugifyHeading` 生成，中文保留，英文转小写，标点归一为连字符，重名追加 `-2`、`-3`。引用锚点前查看解析结果；改标题时同步查找引用。
- 代码块标明 `bash`、`powershell`、`json`、`toml` 等语言；优先给出完整的最小请求，区分必填字段、可选字段与返回数据。
- 可用提示块为 `> [!NOTE]`、`> [!TIP]`、`> [!IMPORTANT]`、`> [!WARNING]`、`> [!CAUTION]`，随后仍用引用行写正文。仅在有实际注意事项时使用。
- 不增加自定义 HTML、脚本、内联 CSS、MDX 或另一套 Markdown 解析器。

接口地址和分组状态使用独立一行的标记：

```markdown
<!-- widget:base-urls -->

<!-- widget:groups -->
```

同一操作的多种语言示例使用代码组。开始和结束标记单独占行，组内只放代码块；每个示例必须完整，不把两套不同操作凑成标签页：

````markdown
<!-- code-group -->

```bash
curl {{BASE_URL}}/v1/models -H "Authorization: Bearer YOUR_API_KEY"
```

```powershell
Invoke-RestMethod -Uri "{{BASE_URL}}/v1/models" -Headers @{ Authorization = "Bearer YOUR_API_KEY" }
```

<!-- /code-group -->
````

## 更新与新增页面

1. 更新已有内容时只改对应 `content/<slug>.md`，需要时同步标题、描述和引用。
2. 新增时创建正文，在 `lib/content.ts` 导入并注册，在 `pages.ts` 的合适分类添加页面。文件名、注册键与 slug 一致；阅读顺序同时决定上一篇/下一篇。
3. 继续使用 `/docs/$slug` 路由，不为每篇文章复制路由或页面组件，不手改 `routeTree.gen.ts`。
4. 当前正文和内容导航为中文；页面控件、空状态、错误、按钮和可访问名称仍遵守项目 i18n。编辑这些 UI 文案前读取 `i18n-translate` 技能，覆盖七种语言，英文原文作键。

## 统一样式与组件

- 保持公共页的导航和主题，使用 `PublicLayout`。桌面左侧分类、中间正文、右侧目录；窄屏用已有 Sheet 导航，正文可读且无页面横向滚动。
- 优先复用 `CopyButton`、`ErrorState`、`EmptyState`、现有 Tabs/Command/Sheet 与共享代码块渲染。变更 UI 前按上级规则检索组件并读取 `shadcn-ui`、React 相关技能。
- 正文区域不包装为浮动大卡片，也不在卡片里嵌套卡片。使用现有字体尺度、间距、`border`、`muted-foreground`、`primary` 语义色和暗色主题。
- 正文标题适配内容区，不使用宣传首屏尺度；不采用按视口连续缩放的字号或负字距，不增加装饰光球和抽象渐变作品。
- 数值沿用 `@/lib/format`、金额沿用 `@/lib/currency`，界面语言进入 Intl 前经 `toIntlLocale` 转换。
- 首页和文档复用 `features/group-status` 的数据与组件。保留无流量、加载、失败、未授权状态；无样本不表示可用率 100%。权限由服务端执行，不能因文章是公开页面绕过接口限制。
- 新的业务部件先判断现有 widget 是否可以组合或扩展；仅有实际能力缺口才新增解析标记，并同步核心回归测试。

## 验证与交付

在 `web/` 执行，按变更范围选择检查，每项通常运行一次：

- 正文、导航或页面注册：`bun run test -- src/features/docs/__tests__/markdown.test.ts`，确认内部文档链接、锚点与标记没有破坏。
- TypeScript/TSX 或 UI：运行受影响测试、`bun run typecheck`，对涉及文件运行 `bun node_modules/oxlint/bin/oxlint -c .oxlintrc.json <paths>`；只用已安装工具。
- 发布内容：`bun run build`。正文编译进入前端产物，并非服务端实时读磁盘；根 Go 可执行文件嵌入前端时也需重新构建，按既有部署流程发布。
- 改导航、布局、搜索或滚动时检查桌面和移动端、长代码/表格、明暗主题及键盘操作。纯文字改动不新增重复测试或重跑无关后端测试。
- 交付说明记录修改的页面、事实来源及实际执行结果。构建不代表真实模型调用、OAuth 或数据库矩阵已验证，未完成项明确列出。
