调用失败时，{{SITE_NAME}} 会返回 HTTP 状态码和 JSON 格式的错误信息，错误信息末尾通常带有本次请求的 ID。本页按状态码列出常见错误的原因和处理方法，并说明如何在使用日志中定位问题、如何反馈。

## 错误响应格式

网关在鉴权、分组和额度校验阶段的错误，以及 OpenAI 格式接口的错误，都使用下面的结构：

```json
{
  "error": {
    "message": "无效的令牌 (request id: 20261005xxxxxxxxxxxxxxxx)",
    "type": "new_api_error",
    "code": ""
  }
}
```

请求进入 Anthropic 格式接口 `/v1/messages` 的转发阶段后，错误按 Anthropic 的结构返回：

```json
{
  "type": "error",
  "error": {
    "type": "...",
    "message": "... (request id: 20261005xxxxxxxxxxxxxxxx)"
  }
}
```

- `message` 末尾的 `(request id: ...)` 就是本次请求的 ID，与响应头 `X-Oneapi-Request-Id` 的值一致。
- `code` 是错误代码，例如 `access_denied`、`insufficient_user_quota`、`model_not_found`，部分错误为空。
- 提示语言跟随账户语言设置或请求头 `Accept-Language`，因此也可能看到英文提示。

## 按状态码排查

### 400 请求参数错误

| 提示信息                                                                  | 原因                                      | 处理方法                                 |
| ------------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------------- |
| `未指定模型名称，模型名称不能为空`                                        | 请求体缺少 `model` 字段                   | 填写模型名，见 [模型列表](/docs/models)  |
| `无效的请求，...`                                                         | 请求体不是合法 JSON，或字段与接口格式不符 | 对照对应接口文档检查请求体               |
| `模型 xxx 的价格尚未由管理员配置，暂时无法使用...`（`model_price_error`） | 该模型还没有定价，暂不开放                | 换用 [模型广场](/pricing) 中已标价的模型 |
| 上游返回的其他参数错误                                                    | 模型不支持某个参数或取值                  | 按提示删除或修改对应参数                 |

请求体过大时返回 HTTP 413（`read_request_body_failed`），常见于以 Base64 内联的大图片或音频，请压缩素材后重试。

### 401 令牌无效

令牌相关的问题都返回同一个提示 `无效的令牌`，常见原因：

- 没有携带令牌，或请求头写法不对，正确写法见 [接口概览](/docs/api-overview)。
- 令牌复制不完整、首尾多了空格，或令牌已被删除。
- 令牌已禁用、已过期，或令牌额度已经用完。

到 [API 密钥](/keys) 页面检查令牌状态。已过期或额度用完的令牌，要先编辑「过期时间」或额度，才能重新启用。

### 403 无权限或额度不足

| 提示信息                                                                            | 原因                                         | 处理方法                                              |
| ----------------------------------------------------------------------------------- | -------------------------------------------- | ----------------------------------------------------- |
| `用户额度不足, 剩余额度: ...` 或 `预扣费额度失败, ...`（`insufficient_user_quota`） | 账户余额不够支付本次请求                     | 到 [钱包](/wallet) 充值，见 [计费说明](/docs/billing) |
| `token quota is not enough, ...`（`pre_consume_token_quota_failed`）                | 令牌设置了额度上限，剩余额度不够             | 编辑令牌提高额度，或开启「无限配额」                  |
| `该令牌无权访问模型 xxx` / `该令牌无权访问任何模型`                                 | 令牌开启了「模型限制」，请求的模型不在列表中 | 编辑令牌调整「模型限制」                              |
| `您的 IP 不在令牌允许访问的列表中`（`access_denied`）                               | 令牌设置了 IP 白名单                         | 把当前出口 IP 加入白名单，或清空白名单                |
| `无权访问 xxx 分组` / `分组 xxx 已被弃用`                                           | 令牌绑定的分组当前不可用                     | 编辑令牌换一个可用分组，见 [分组说明](/docs/groups)   |
| `用户已被封禁`                                                                      | 账户已被停用                                 | 联系管理员                                            |

令牌的编辑入口在 [API 密钥](/keys) 页面，各字段的含义见 [创建令牌](/docs/api-keys)。

### 404 与 501 接口不存在

| 提示信息                                 | 原因                                                 | 处理方法                                     |
| ---------------------------------------- | ---------------------------------------------------- | -------------------------------------------- |
| `Invalid URL (POST /v1/xxx)`（HTTP 404） | 接口路径写错，常见于 Base URL 少了或多写了 `/v1`     | 对照 [接口概览](/docs/api-overview) 检查地址 |
| `API not implemented`（HTTP 501）        | 调用了未实现的接口，如 `/v1/files`、`/v1/fine-tunes` | 改用已支持的接口                             |

### 429 请求过多

| 提示信息                                   | 原因                   | 处理方法                                 |
| ------------------------------------------ | ---------------------- | ---------------------------------------- |
| `您已达到请求数限制：N分钟内最多请求M次`   | 超过站点设置的请求频率 | 等时间窗口过去再请求，降低并发           |
| `您已达到总请求数限制：...包括失败次数...` | 失败的请求也计入总次数 | 先修正导致失败的请求，避免客户端无限重试 |
| 上游返回的 429                             | 上游号池或模型方限流   | 稍后重试，或换用其他分组                 |

### 500 / 502 / 503 / 504

| 状态码                            | 常见原因                                    | 处理方法                             |
| --------------------------------- | ------------------------------------------- | ------------------------------------ |
| 500                               | 网关内部错误，如 `数据库出错，请联系管理员` | 稍后重试，持续出现请带上请求 ID 反馈 |
| 502 / 504                         | 上游服务异常或响应超时                      | 稍后重试；长回复建议开启流式输出     |
| 503（`model_not_found`）          | 当前分组下该模型没有可用线路                | 见下方「模型在当前分组不可用」       |
| 503（`system_cpu_overloaded` 等） | 服务器负载过高，暂时拒绝新请求              | 稍后重试                             |

## 模型在当前分组不可用

这是最常见的 503 错误，提示类似：

```text
分组 codex-plus 下模型 gpt-x 无可用渠道（distributor） (request id: ...)
获取分组 auto(codex-plus) 下模型 gpt-x 的可用渠道失败（distributor）：...
```

令牌使用自动分组时，提示里的分组可能显示为 `auto` 或 `auto(实际尝试的分组)`。按以下顺序排查：

1. 检查模型名的拼写和大小写，必须与 [模型广场](/pricing) 中显示的名称完全一致。
2. 用同一个令牌调用 `GET {{BASE_URL}}/v1/models`，确认模型在返回列表中。不在列表中说明令牌所属分组不包含该模型，需要换用对应分组的令牌，见 [分组说明](/docs/groups)。
3. 模型在列表中仍然报错，通常是该分组的线路暂时不可用。可以稍后重试，参考分组的 24 小时可用率，或改用其他分组的令牌。

## 上游返回的错误

请求已经转发到上游后出现的错误，提示内容来自上游服务商，网关会原样返回并在末尾附上请求 ID。例如 Codex 提示 `Selected model is at capacity. Please try a different model`，通常是 GPT 官方算力不足导致的，只能等待官方恢复，或暂时换用其他模型。

## 在使用日志中排查

控制台左侧菜单的日志页面：

| 页面                    | 内容                                                                                                                  |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------- |
| [使用日志](/usage-logs) | 每次调用的时间、令牌、分组、模型、Token 用量、费用和耗时；可按「模型名称」「分组」「类型」「令牌名称」「请求 ID」筛选 |
| 任务日志                | 视频等异步任务的「任务 ID」「状态」「进度」，失败任务可在「详情」中查看「失败原因」                                   |
| 审计日志                | 登录、账户安全等操作记录                                                                                              |

- 点击日志的「详情」可以看到该请求的「请求 ID」和计费明细。
- 被拒绝的请求（例如令牌无效、余额不足）不会扣费，通常也不会产生消耗记录。
- 视频等异步任务失败后，系统会自动退还预扣的费用，使用日志中会出现「退款」类型的记录。

## 反馈问题

反馈前请准备以下信息：

1. 请求 ID：响应头 `X-Oneapi-Request-Id`，或错误信息末尾 `(request id: ...)` 中的值。
2. 发生时间、使用的模型和令牌所属分组。
3. 完整的错误信息，以及使用的客户端或调用方式。

> [!CAUTION]
> 反馈时只提供令牌名称，不要发送完整的 API Key。令牌一旦泄露，请立即到 [API 密钥](/keys) 页面删除并重新创建。
